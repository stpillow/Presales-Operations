# M3 brief: the daily loop

Read this, then `PROMPT.md` sections 1, 2, 5 (your screen's row), `CLAUDE.md`, and the files named under "What exists". Build only your screen's files. Done when Shawn can run Session A on his phone end to end, do a morning check, and watch the next Session A's prescriptions change according to the reading.

## Non-negotiables

1. **Logic only in `src/rules/`.** Screens render and collect input. They call `planSession`, `prescribe`, `sessionReading`, `morningReading`, `combinedReading`, `scheduledSession`, `weekOf`, `isDeloadWeek`, `afterMorningCheck`, `clearRedFlag`, `stopMessage`, `healthySideTargets`, `effectiveReading`. If you need a decision that isn't there, add a pure function with a test in `src/rules/` (and only there); do not decide in a component.
2. **No meaning by color alone.** Shawn is colorblind. Every state is a word or a mark: `ReadingWord` for readings, `Tap` for yes/no, text labels on buttons. Green is at most one accent word per screen, through `text-green-bright`.
3. **One hand, weak signal, 60-second rest windows.** Every logging interaction under 10 seconds without reading. 44 px targets (`tap` utility, `Button`, `Stepper`, `Tap`). Numeric keypads (`Stepper` sets `inputMode`). No modal that traps; a sheet or an inline section the user can leave. Nothing fetches anything.
4. **spdc tokens only.** Tailwind's palette is cleared; use `bg-navy`, `bg-navy-lift`, `bg-ink`, `bg-paper`, `text-on-dark`, `text-on-dark-dim`, `text-on-dark-muted`, `text-on-dark-faint`, `text-on-light`, `text-green-bright`, `border-on-dark-faint`; type `text-label|small|body|lead|h3|h2|h1`, `font-display|sans|mono`; radii `rounded-sm|md`; spacing on the 4 px scale. Fraunces for the screen title only (`Screen` does it); Plex Mono only for short labels. No gradients, glows, icons, illustrations, nested cards.
5. **Every write through `src/db/repo.ts`** (`upsertSet`, `putWorkout`, `updateWorkout`, `addMorningCheck`, `saveSettings`), never `db.table.put` from a screen. Reads through `src/db/hooks.ts` (`useSettings`, `useHistory`, `useWorkout`, `useSetsFor`), which are live queries: the screen re-renders when the data changes.
6. **Today comes from `useToday()`** (`src/app/today.ts`), never `new Date()` in a screen except to stamp `loggedAt`/`startedAt`/`finishedAt` ISO strings.
7. **Nothing async fails silently.** Catch rejected writes and show one sentence in words.
8. Strict TypeScript (`noUncheckedIndexedAccess`), oxlint clean, `npm run check` green before you finish. Add Vitest tests for any pure helper you write (put helpers in your screen's `*.helpers.ts` file; component rendering tests are not expected, there is no DOM test harness installed).

## What exists

- `src/app/router.ts`: `useRoute()`, `navigate({ name: 'today' })`, routes `today | session/:workoutId | morning | run | week | progress | gates | program | settings | more`.
- `src/app/session.ts`: `planSession({ template, week, settings, history, chosenExercise? })` returns `SlotPlan[]` (slot, exercise, substitutions, prescriptions per side, injured side first). `currentTemplate(settings, 'A'|'B'|'C')`. `PROGRAM` is the validated seed (`program.phases`, `program.weeklyTemplate`, `program.redFlags`, `program.warmUp`, `program.notFlags`, …). `exerciseById`, `templateFor` in `src/program/program.ts`.
- `src/db/repo.ts`: writes listed above, `setId(workoutId, slotId, side, setNumber)` (a set's id is its coordinates: logging it twice overwrites), `loadHistory()`, `resetAll()`.
- `src/rules/*`: read the function signatures; the tests beside them show every behavior.
- `src/components/`: `Screen` (title + lead + content, tab bar height reserved), `Button` (`primary | secondary | quiet`, `wide`), `Stepper`, `Tap`, `ReadingWord` + `readingSentence`, `RestTimer` (pass a stored `startedAt` ms instant; it recomputes from the clock, so a locked screen can't stretch it).
- `src/App.tsx` routes to `Today`, `SessionRunner({ workoutId })`, `MorningCheck`, `Settings`, `More`, and placeholders. Seeds settings on first run. Do not edit it.
- Schemas in `src/schema/`: `Workout` (status `planned | in-progress | finished | abandoned`), `SetLog` (`side`, `load`, `loadUnit`, `reps` or `seconds` exactly one, `rpe`, `painDuring`, `stopped`, `stopReason` enum, `heightIn`, `rangeStopDeg`, `stage`, `loggedAt`), `MorningCheck`, `Settings` (`injuredSide`, `startDate`, `dumbbellMax`, `restTimerSeconds`, `painPerSet`, `currentPhase`, `phaseEnteredWeek`, `redFlag`).

## Screens

**Today** (`PROMPT.md` section 5, row 1). From `useToday()`, `useSettings()`, `useHistory()`: `scheduledSession(today, settings.startDate, PROGRAM.weeklyTemplate, history.sessionMoves)`. Show: the date in words; phase (`settings.currentPhase`, name from `PROGRAM.phases`) and week (`weekOf`); a "Deload week" badge in words when `isDeloadWeek(week)`; the scheduled session ("Session A", "Run: MBR", "Off: Kona walk and mobility only"); yesterday's reading in words from `subjectReadings` for `addDays(today, -1)` (or "No session yesterday"); one Start button. Start: if a workout for today's date and template exists and is `in-progress`, open it; otherwise `putWorkout({ id, date, templateId, phase, week, isDeload, startedAt, status: 'in-progress' })` and `navigate({ name: 'session', workoutId })`. Run days: a button to the run logger (placeholder in M4) and a line saying the run logger arrives in M4. Before the start date: "Week 1 starts Monday Nov 2" and the Start button disabled. Red-flag state (`settings.redFlag.active`): replace everything with `stopMessage(settings.redFlag, PROGRAM.redFlags)`: the headline, the flagged items, and a line that progression is suspended until it is cleared in Settings. If today's workout is already `finished`: say so, with its reading in words, and a button to the Morning check. Phase 4 (`currentPhase === 4`): say its sessions are not written yet.

**Session runner** (row 2). Read `docs/session-runner-design.md` first; it is the design to build. Inputs: `useWorkout(workoutId)`, `useSetsFor(workoutId)`, `useSettings()`, `useHistory()`; `planSession({ template: templateFor(workout.phase, letter from workout.templateId), week: workout.week, settings, history, chosenExercise })` where `chosenExercise` is this session's swaps (component state). Must do: warm-up checklist at the top (`PROGRAM.warmUp.lift`, the circuit minutes for the phase), nothing logged for it; slots in order with cues visible; superset groups (`slot.groupId`) shown as one group; optional slots skippable; per set: load, reps or seconds, RPE and pain as steppers prefilled from the prescription (per-set `perSet` when present, else `load`/`repsTarget`; `heightIn`, `rangeStopDeg`, `stage` shown and logged when the slot has them); pain once per exercise when `settings.painPerSet` is false (one stepper per exercise, its value written on every set of that exercise); a side toggle on unilateral slots that starts on the injured side and shows the healthy side's rep budget (`healthySideTargets` of the injured side's logged sets); marking a set done calls `upsertSet` and starts the rest timer (`settings.restTimerSeconds`); a Swap button listing the slot's substitutions in order (changes `chosenExercise` for this session; sets log with the chosen `exerciseId`); a Stop this exercise control that logs the current set with `stopped: true` and a `stopReason` picked from the enum (sharp joint-line pain first); Finish asks for max pain during the session (`maxPainDuring`), sets `finishedAt` and `status: 'finished'`, and shows a summary: per exercise its session reading in words (`sessionReading`) and the one-line note of what that means next time, then a button to Today. Abandon (leave early) sets `status: 'abandoned'` with what was logged kept. Resuming an in-progress workout shows logged sets as done.

**Morning check** (row 3). Four `Tap`s (stiffness gone within 30 minutes; worse than yesterday; visible swelling; warmth), a pain-change `Stepper` (−10 to 10), the red-flag checklist from `PROGRAM.redFlags` as `Tap`s with `PROGRAM.notFlags` shown under it as the "not flags" line, an optional note. `appliesTo`: the most recent workout or run dated yesterday (`addDays(today, -1)`), else null; say in words which session the check is for. Save: `addMorningCheck`, then if any red flag: `saveSettings({ ...settings, redFlag: afterMorningCheck(settings.redFlag, check) })`. Then show the reading in words (`morningReading`) and, for yesterday's workout, one sentence per exercise of what changes next time (`planSession` for that template with the new history, each prescription's `note`), then a button to Today.

**Settings** (row 9). Injured side (two `Tap`-style choices), start date (date input; must be a Monday, `isMonday`, say so otherwise), dumbbell max (presets 60, 75, 80 and a `Stepper`), rest timer seconds (`Stepper`, 15 s steps), pain per set (`Tap`), current phase and the week it was entered (read-only here, with a line that Gates advances it in M5), clear the red-flag state (a note field and a button; `clearRedFlag` refuses an empty note; show the refusal in words), reset all data (two taps: "Reset all data" then "Yes, erase everything"; `resetAll()` then re-seed via `ensureSettings(defaultSettings(PROGRAM))`), and lines saying export and import arrive in M6. Every change saves immediately through `saveSettings` with a "Saved" word that appears for a moment.
